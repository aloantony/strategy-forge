## 1. Overview

This catalogue is the single source of truth for TASK-014b and TASK-014c. It answers three questions for every indicator the Strategy Builder will support:

1. What exact DataFrame column names does it produce?
2. Is that column already in the DataFrame when a strategy's `prepare_dataframe` is called (pre-computed), or must `prepare_dataframe` compute it?
3. What parameters are user-configurable vs. baked into the global config?

Source files read: `data_feed.py`, `config.py`, `strategies/strategy_ema_rsi_trend.py`, `strategies/strategy_bollinger_rsi_reversion.py`, `strategies/strategy_donchian_breakout.py`, `main.py`.

## 2. DataFrame Column Inventory

### 2.1 Raw MT5 columns (always present, never generated by strategies)

These come directly from `mt5.copy_rates_from_pos()` and are present in every DataFrame a strategy receives.

| Column | Type | Description |
|--------|------|-------------|
| `time` | datetime (UTC) | Candle open time |
| `open` | float | Open price |
| `high` | float | High price |
| `low` | float | Low price |
| `close` | float | Close price |
| `tick_volume` | int | Tick count (proxy for volume on CFDs) |
| `spread` | int | Spread in points |
| `real_volume` | int | Real volume (zero on most CFDs) |

### 2.2 Pre-computed by `data_feed` (always present before strategy runs)

The bot pipeline calls these four functions on every market cycle, before any strategy processes the DataFrame:

```
get_rates_df()
  → add_source_columns()
  → add_baseline_bands()
  → add_supertrend()
  → add_tci()
```

#### 2.2.1 Source columns — `add_source_columns(df, source_mode)`

| Column | Formula | Notes |
|--------|---------|-------|
| `OHLC4` | (open + high + low + close) / 4 | Always present |
| `HLC3` | (high + low + close) / 3 | Always present |
| `HL2` | (high + low) / 2 | Always present |
| `CLOSE` | close (alias) | Always present |
| `h_set` | One of OHLC4/HLC3/HL2/CLOSE depending on `SOURCE_MODE` | Currently `OHLC4` |
| `l_set` | Same as h_set | Currently `OHLC4` |

`SOURCE_MODE` is `config.SOURCE_MODE = "OHLC4"`. Strategies receive `h_set` and `l_set` but should generally use `close` for condition operands — `h_set`/`l_set` are pipeline internals consumed by `add_baseline_bands`.

#### 2.2.2 Baseline bands — `add_baseline_bands(df, ma_length, atr_length, atr_mult)`

Called with `config.MA_LENGTH=20`, `config.ATR_LENGTH=14`, `config.ATR_MULT=0.5`.

| Column | Formula | Config key | Default |
|--------|---------|-----------|---------|
| `average` | SMA(h_set, window=MA_LENGTH) | `MA_LENGTH` | 20 |
| `atr` | SMA(TR, window=ATR_LENGTH) | `ATR_LENGTH` | 14 |
| `upper` | average + atr × ATR_MULT | `ATR_MULT` | 0.5 |
| `lower` | average - atr × ATR_MULT | `ATR_MULT` | 0.5 |

**Important**: `atr` here uses a simple moving average of True Range. The strategies' own `atr_14` column uses EWM (exponential weighted) — they are numerically different. See Section 3 (EMA-ATR) for details.

#### 2.2.3 Supertrend — `add_supertrend(df, atr_length, atr_mult, source_col, use_hma, hma_length)`

Called with `config.SUPERTREND_ATR_LENGTH=10`, `config.SUPERTREND_MULT=3.0`, `config.SUPERTREND_SOURCE="close"`, `config.SUPERTREND_USE_HMA=True`, `config.HMA_LENGTH=55`.

| Column | Formula/Meaning | Config key | Default |
|--------|----------------|-----------|---------|
| `hma` | HMA(close, HMA_LENGTH) — Hull Moving Average | `HMA_LENGTH` | 55 |
| `atr_st_10` | SMA(TR, 10) — internal ATR for Supertrend | `SUPERTREND_ATR_LENGTH` | 10 |
| `supertrend` | Supertrend band value (upper or lower depending on direction) | — | — |
| `supertrend_dir` | 1 = bullish, -1 = bearish, 0 = no data | — | — |
| `supertrend_up` | `supertrend` where dir==1, else NaN | — | — |
| `supertrend_down` | `supertrend` where dir==-1, else NaN | — | — |

Note: `atr_st_<N>` column name is dynamic (`f"atr_st_{atr_length}"`). With default config it is `atr_st_10`. Strategies should not reference this internal column directly.

#### 2.2.4 TCI oscillator — `add_tci(df, fast_length, slow_length, signal_length)`

Called with `config.TCI_FAST=9`, `config.TCI_SLOW=21`, `config.TCI_SIGNAL=5`.

| Column | Formula | Config key | Default |
|--------|---------|-----------|---------|
| `tci` | (EMA(close, fast) − EMA(close, slow)) / ATR | `TCI_FAST`, `TCI_SLOW` | 9, 21 |
| `tci_signal` | EMA(tci, signal_length) | `TCI_SIGNAL` | 5 |
| `tci_hist` | tci − tci_signal | — | — |

## 3. Strategy-Computed Indicators (require `prepare_dataframe`)

These columns are NOT in the DataFrame when a strategy is called. The generated strategy's `prepare_dataframe` function must compute them. The Builder generates a `prepare_dataframe` that computes exactly the indicators selected by the user.

### 3.1 EMA — Exponential Moving Average

**User-visible name**: EMA
**Configurable parameter**: Period (integer ≥ 1)
**Formula**: `close.ewm(span=period, adjust=False).mean()`
**Column name convention**: `ema_<period>` (e.g. `ema_9`, `ema_21`, `ema_34`)

**Observed in strategies**:
- `ema_fast` (period=9) in `strategy_ema_rsi_trend`
- `ema_slow` (period=21) in `strategy_ema_rsi_trend`
- `ema_filter` (period=34) in `strategy_donchian_breakout`

**Builder column naming**: Use `ema_<period>` (e.g. `ema_9`, `ema_21`). The existing strategies used semantic names (`ema_fast`, `ema_filter`) but the Builder should use a canonical, parameter-derived name to avoid ambiguity when multiple EMAs of different periods coexist in one strategy. TASK-014c must decide whether to adopt `ema_<period>` universally.

**Source**: Requires `prepare_dataframe`. Input: `close`.

---

### 3.2 RSI — Relative Strength Index

**User-visible name**: RSI
**Configurable parameter**: Period (integer ≥ 2)
**Formula**: Wilder smoothing (EWM alpha=1/period) on gains/losses
**Column name convention**: `rsi_<period>` (e.g. `rsi_14`, `rsi_7`)

**Observed in strategies**:
- `rsi_14` (period=14) in `strategy_ema_rsi_trend`
- `rsi_7` (period=7) in `strategy_bollinger_rsi_reversion`

**Source**: Requires `prepare_dataframe`. Input: `close`.

---

### 3.3 Bollinger Bands

**User-visible name**: Bollinger Bands
**Configurable parameters**:
- Period (integer ≥ 2) — rolling window for SMA and std
- Multiplier (float > 0) — how many standard deviations for upper/lower

**Column names**: Three columns are produced together — they cannot be selected individually; selecting Bollinger Bands gives all three.

| Column | Formula |
|--------|---------|
| `bb_basis_<period>` | SMA(close, period) |
| `bb_upper_<period>` | bb_basis + std(close, period) × multiplier |
| `bb_lower_<period>` | bb_basis - std(close, period) × multiplier |
| `bb_width_pct_<period>` | (bb_upper - bb_lower) / bb_basis |

**Observed in strategies**: `bb_basis`, `bb_upper`, `bb_lower`, `bb_width_pct` (period=20, mult=1.8) in `strategy_bollinger_rsi_reversion`. Existing column names have no period suffix — the Builder should adopt `bb_<band>_<period>` to support multiple Bollinger configurations in one strategy.

**Source**: Requires `prepare_dataframe`. Input: `close`.

---

### 3.4 Donchian Channel

**User-visible name**: Donchian Channel
**Configurable parameter**: Period (integer ≥ 2)
**Formula**: rolling max/min of high/low over (period) candles, shifted by 1 (uses previous completed channel)

| Column | Formula |
|--------|---------|
| `donchian_high_<period>` | rolling_max(high, period).shift(1) |
| `donchian_low_<period>` | rolling_min(low, period).shift(1) |
| `donchian_mid_<period>` | (donchian_high + donchian_low) / 2 |

**Observed in strategies**: `donchian_high`, `donchian_low`, `donchian_mid` (period=12) in `strategy_donchian_breakout`.

**Note on shift(1)**: The `.shift(1)` means the channel uses candles up to (but not including) the current candle. This prevents look-ahead bias and matches the observed implementation exactly.

**Source**: Requires `prepare_dataframe`. Inputs: `high`, `low`.

---

### 3.5 ATR — Average True Range (EWM method)

**User-visible name**: ATR
**Configurable parameter**: Period (integer ≥ 1)
**Formula**: EWM(TR, alpha=1/period, min_periods=period) — Wilder smoothing
**Column name convention**: `atr_<period>` (e.g. `atr_14`)

**Observed in strategies**:
- `atr_14` (period=14) in both `strategy_ema_rsi_trend` and `strategy_donchian_breakout`

**Distinction from pre-computed `atr`**: The pre-computed `atr` column uses a simple moving average of True Range (SMA method, from `add_baseline_bands`). Strategy-computed `atr_<N>` uses EWM (Wilder smoothing). They are numerically different even when both use period=14. The Builder must always generate EWM-based ATR in `prepare_dataframe` and use `atr_<period>` column names, not the pre-computed `atr` column.

**Source**: Requires `prepare_dataframe`. Inputs: `high`, `low`, `close`.

---

### 3.6 ATR% — ATR as Percentage of Price

**User-visible name**: ATR%
**Configurable parameter**: None (derived from ATR with same period)
**Formula**: `atr_<period> / close`
**Column name convention**: `atr_pct_<period>`

**Observed in strategies**: `atr_pct` (derived from `atr_14`) in `strategy_ema_rsi_trend` and `strategy_donchian_breakout`.

**Source**: Derived; only present if ATR for the same period is computed. If the user selects ATR, ATR% is always co-produced at no extra cost.

---

### 3.7 VWAP — Volume-Weighted Average Price (Intraday)

**User-visible name**: VWAP
**Configurable parameters**: None (resets daily)
**Formula**: Cumulative (typical_price × volume) / cumulative volume, grouped by calendar day (UTC)
**Column name**: `vwap`

**Observed in strategies**: `vwap` in `strategy_ema_rsi_trend`.

**Important caveat**: VWAP resets at session start (UTC midnight). It is only meaningful on intraday timeframes (M1–H1). On D1 it is identical to the day's typical price. The Builder must display a warning or disable VWAP for D1.

**Volume source**: Uses `tick_volume` if present, else `volume`, else falls back to 1.0 (constant). On MT5 CFD instruments `tick_volume` is the effective proxy.

**Source**: Requires `prepare_dataframe`. Inputs: `high`, `low`, `close`, `tick_volume` (or `volume`), `time`.

---

### 3.8 Volume Ratio

**User-visible name**: Volume Ratio
**Configurable parameter**: Lookback period (integer ≥ 2) — rolling window for the moving average of volume
**Formula**: `tick_volume / rolling_mean(tick_volume, lookback)`
**Column name convention**: `volume_ratio_<lookback>`

**Observed in strategies**:
- `volume_ratio` (lookback=30) in `strategy_ema_rsi_trend`
- `volume_ratio` (lookback=30) in `strategy_bollinger_rsi_reversion`
- `volume_ratio` (lookback=24) in `strategy_donchian_breakout`

All three existing strategies used the unqualified name `volume_ratio`. The Builder should use `volume_ratio_<lookback>` to avoid collision when different lookback values coexist.

**Source**: Requires `prepare_dataframe`. Input: `tick_volume` (or `volume` fallback).

---

### 3.9 SMA — Simple Moving Average (baseline)

**User-visible name**: SMA
**Configurable parameter**: Period (integer ≥ 1)
**Formula**: `close.rolling(window=period).mean()`
**Column name convention**: `sma_<period>` (e.g. `sma_20`, `sma_50`)

**Note**: The pre-computed `average` column is a SMA of `h_set` (not `close`) with period=`MA_LENGTH`. The Builder should generate a separate SMA of `close` in `prepare_dataframe` under the name `sma_<period>`, rather than aliasing the pre-computed `average`. This avoids coupling to the global `SOURCE_MODE` setting.

**Source**: Requires `prepare_dataframe`. Input: `close`.

---

### 3.10 HMA — Hull Moving Average (pre-computed, parameter-locked)

**User-visible name**: HMA
**Configurable parameter**: None in the Builder for v1 — see note
**Formula**: WMA(2 × WMA(close, period/2) − WMA(close, period), √period)
**Column name**: `hma` (pre-computed, period=`HMA_LENGTH`=55)

The `hma` column is pre-computed by `add_supertrend` with `config.HMA_LENGTH=55`. A strategy can read `df["hma"]` directly without `prepare_dataframe`.

**Builder recommendation for v1**: Expose as a read-only indicator (user can use `hma` as a condition operand, but cannot change the period). Period is governed by the global config. If per-strategy HMA with a custom period is needed in a future version, it would require `prepare_dataframe`.

**Source**: Pre-computed. Period is `config.HMA_LENGTH=55` — **baked into global config; not per-strategy configurable in v1**.

---

### 3.11 Supertrend (pre-computed, parameter-locked)

**User-visible name**: Supertrend
**Configurable parameters**: None in v1 — see note
**Columns available**: `supertrend`, `supertrend_dir`, `supertrend_up`, `supertrend_down`

All Supertrend columns are pre-computed with global config (`SUPERTREND_ATR_LENGTH=10`, `SUPERTREND_MULT=3.0`). Usable as condition operands directly.

**Useful condition operand**: `supertrend_dir` — comparing to literal 1 or -1 is the idiomatic Supertrend condition:
- `supertrend_dir == 1` → bullish trend
- `supertrend_dir == -1` → bearish trend

**Source**: Pre-computed. All parameters baked into global config — **not per-strategy configurable in v1**.

---

### 3.12 TCI (pre-computed, parameter-locked)

**User-visible name**: TCI
**Configurable parameters**: None in v1
**Columns available**: `tci`, `tci_signal`, `tci_hist`

Pre-computed with `TCI_FAST=9`, `TCI_SLOW=21`, `TCI_SIGNAL=5`.

**Source**: Pre-computed. All parameters baked into global config — **not per-strategy configurable in v1**.

### 3.13 ADX_DI — Average Directional Index + Directional Indicators

_Added: TASK-019 (2026-04-06)_

**User-visible name**: ADX + DI
**Configurable parameter**: Period (integer ≥ 2, default 14)
**Indicator ID**: `"ADX_DI"`
**Formula**: Wilder smoothing (EWM alpha=1/period) — same method as ATR (EWM) and RSI

**Columns produced** (5 total, all via `prepare_dataframe`):

| Column | Meaning | Range |
|--------|---------|-------|
| `adx_<period>` | Average Directional Index — trend strength | [0, 100] |
| `plus_di_<period>` | +Directional Indicator — upward movement force | [0, 100] |
| `minus_di_<period>` | −Directional Indicator — downward movement force | [0, 100] |
| `plus_di_cross_<period>` | 1 on candle where +DI crossed above -DI, else 0 | {0, 1} |
| `minus_di_cross_<period>` | 1 on candle where -DI crossed above +DI, else 0 | {0, 1} |

**Inputs**: `high`, `low`, `close`
**Source**: Requires `prepare_dataframe`. Helper function `_adx_di(high, low, close, length)`.
**Lookback**: First reliable ADX at row `2*period - 1` (row 27 for period=14). Crossover columns valid from row `2*period`. With n=500 rows, always in stable zone.

**Crossover design note**: The crossover columns are pre-computed boolean flags, not a new ConditionNode type. The condition `+DI crosses above -DI` is expressed as `plus_di_cross_14 > 0` in the standard condition tree. No emitter changes required. Full design rationale in `agents/specs/TASK-019-adx-di-crossover-spec.md`.

## 5. Valid Condition Operands for the Builder

The Builder's condition editor must restrict left/right operands to known columns. The complete set of valid operand column names, grouped by source:

### 5.1 Always-available (no indicators needed)
`open`, `high`, `low`, `close`, `OHLC4`, `HLC3`, `HL2`, `tick_volume`

`average`, `atr`, `upper`, `lower`, `hma`, `supertrend`, `supertrend_dir`, `tci`, `tci_signal`, `tci_hist`

`ema_<period>`, `rsi_<period>`, `bb_basis_<period>`, `bb_upper_<period>`, `bb_lower_<period>`, `bb_width_pct_<period>`, `donchian_high_<period>`, `donchian_low_<period>`, `donchian_mid_<period>`, `atr_<period>`, `atr_pct_<period>`, `vwap`, `volume_ratio_<lookback>`, `sma_<period>`

**The condition editor must only allow referencing columns that correspond to indicators the user has actually added to the strategy.** Referencing a column not in the current indicator list must be a validation error at save time.

## 6. MT5 Timeframe Constants

From `main.py` `TIMEFRAME_MAP` (lines 24–32), the confirmed safe set for the Builder's timeframe selector:

| Display string | MT5 constant | Approximate candle duration |
|---------------|-------------|----------------------------|
| `M1` | `mt5.TIMEFRAME_M1` | 1 minute |
| `M5` | `mt5.TIMEFRAME_M5` | 5 minutes |
| `M15` | `mt5.TIMEFRAME_M15` | 15 minutes |
| `M30` | `mt5.TIMEFRAME_M30` | 30 minutes |
| `H1` | `mt5.TIMEFRAME_H1` | 1 hour |
| `H4` | `mt5.TIMEFRAME_H4` | 4 hours |
| `D1` | `mt5.TIMEFRAME_D1` | 1 day |

These 7 values are the safe set. MT5 supports additional constants (`W1`, `MN1`) but they are not in `TIMEFRAME_MAP` and are not validated by `_resolve_timeframe_value()`. The Builder must restrict the selector to these 7 values only.

**Fallback behavior**: If a strategy's `TIMEFRAME` is missing or unresolvable, `load_active_strategies()` falls back to `config.TIMEFRAME` (which defaults to `mt5.TIMEFRAME_M1`). The Builder should always write an explicit `TIMEFRAME` constant in the generated file to avoid relying on this fallback.

**VWAP restriction**: Expose a warning in the GUI when VWAP is selected as an indicator and the timeframe is `D1` — VWAP is meaningless on daily bars.

## 7. Config-Baked Parameters — Builder Handling Notes

The following indicators have parameters that are controlled by global `config.py` variables. The Builder must decide for each whether to:
- **(A) Expose in the form** — strategy generates its own parameter constants and computes the indicator in `prepare_dataframe`
- **(B) Reuse global** — strategy reads the pre-computed column, inheriting whatever the global config value is

| Global config key | Default | Affects column | Current approach | Builder recommendation |
|-------------------|---------|----------------|-----------------|----------------------|
| `MA_LENGTH` | 20 | `average` | Pre-computed, global | Option B (reuse `average`) or Option A (generate SMA with custom period via `sma_<N>`) |
| `ATR_LENGTH` | 14 | `atr` | Pre-computed, global | Option A — generate `atr_<period>` in prepare_dataframe; do NOT alias the pre-computed `atr` |
| `ATR_MULT` | 0.5 | `upper`, `lower` | Pre-computed, global | Option B only; the Builder does not expose `upper`/`lower` band parameterization in v1 |
| `SUPERTREND_ATR_LENGTH` | 10 | `atr_st_10`, `supertrend` | Pre-computed, global | Option B only — Builder exposes Supertrend as a read-only pre-computed indicator |
| `HMA_LENGTH` | 55 | `hma` | Pre-computed, global | Option B only — Builder exposes HMA as a read-only pre-computed indicator |
| `TCI_FAST`/`TCI_SLOW`/`TCI_SIGNAL` | 9/21/5 | `tci`, `tci_signal`, `tci_hist` | Pre-computed, global | Option B only |

**Key constraint for ATR**: Because the pre-computed `atr` uses SMA smoothing and strategy-computed ATR uses EWM smoothing, they are numerically different even at the same period. If a user adds ATR to their strategy and sets period=14, the Builder must generate `atr_14` in `prepare_dataframe` (EWM method), not reference the pre-computed `atr` column. This is consistent with all three existing strategy files.

## 8. Signal Output Columns (always produced by `compute_signals`)

Every generated strategy must produce these four columns from `compute_signals`:

| Column | Type | Meaning |
|--------|------|---------|
| `up_sig` | int (0/1) | Buy signal on this candle |
| `dn_sig` | int (0/1) | Sell signal on this candle |
| `long_setup` | int (0/1) | Intermediate long condition met (optional for GUI display) |
| `short_setup` | int (0/1) | Intermediate short condition met (optional for GUI display) |

For the Builder's generated strategies, `long_setup` and `short_setup` can be identical to `up_sig`/`dn_sig` (no multi-step setup pattern required). The distinction matters in the existing hand-written strategies where `long_setup` is a prerequisite and `up_sig` is a confirmation trigger — but the Builder can simplify this to a single-pass condition.

## 9. Confirmed Findings for TASK-014b

The following are constraints that TASK-014b must respect:

1. **Column name disambiguation**: The Builder uses `ema_<period>`, `rsi_<period>`, `atr_<period>`, `sma_<period>`, `bb_*_<period>`, `donchian_*_<period>`, `volume_ratio_<lookback>` as canonical names. A single strategy can have two EMAs of different periods (`ema_9`, `ema_21`) coexisting without collision.

2. **Condition operand types**: A condition leaf node's `left` is always a column name string. A condition leaf node's `right` is either a column name string or a numeric scalar (float/int). The type tag must distinguish them to handle code generation correctly (`df.iloc[-2]["col"]` vs. a literal value).

3. **No look-ahead**: All conditions use `df.iloc[-2]` (the last *closed* candle), consistent with all three existing strategies.

4. **Valid operators for the condition editor**: `<`, `>`, `<=`, `>=`, `==`, `!=`. No string operators needed — all indicator values are numeric.

5. **Minimum indicators for v1 Builder**: EMA, RSI, Bollinger Bands, Donchian Channel, ATR. VWAP, Volume Ratio, SMA, and the pre-computed indicators (Supertrend, TCI, HMA) are available as condition operands once the column naming is settled.
