Runtime

Runtime v1 (planes)

El runtime v1 convierte cada decisión de estrategia en un plan estructurado, lo valida, lo ejecuta contra el broker y persiste todo. Vive en src/runtime/ y se orquesta desde main._run_v1_strategy_cycle.

Pipeline

El ciclo (_run_v1_strategy_cycle)

  1. Cargar estado: StrategyStateStore.load(instance_id) → (state, revision).
  2. Construir contexto: StrategyContextBuilder.build(...).
  3. initial_state: si revision == 0 y el módulo es v1 con initial_state.
  4. decidir: module.decide(context, state) (v1) o LegacyStrategyAdapter.decide(...) (legacy). Devuelve {plan, next_state}.
  5. persistir plan (status validated) y evento plan_received.
  6. ejecutar si PLAN_EXECUTOR_ENABLED + mercado abierto + hay acciones: PlanInterpreter.validate_and_normalize → ExecutionEngine.execute_plan (bajo ORDER_EXECUTION_LOCK).
  7. persistir next_state con revision + 1.

El contexto (StrategyContextBuilder)

El dict que recibe decide() tiene estas secciones:

run
modo, iteration_id, strategy_key, símbolo, timeframe, revisiones.
clock
now_utc, broker_time, trading_day, weekday, market_open.
market
quote (bid/ask/mid/spread) y frames[tf].bars (cada barra con OHLCV + indicators).
instrument
point, tick_size, tick_value, volúmenes, stop/freeze level.
account
balance, equity, margin_used/free, currency.
portfolio
exposición bruta/neta y riesgo por símbolo/estrategia.
execution
owned_legs, owned_entry_groups, broker_positions.
engine
capacidades + max_actions_per_cycle = 20.

Adaptador legacy

LegacyStrategyAdapter.decide reconstruye el DataFrame desde market.frames, ejecuta el pipeline legacy y traduce la señal a acciones: buy/sell abren la posición correspondiente (cerrando antes la opuesta); none no genera acciones. El plan lleva meta.origin = "legacy_adapter" y meta.legacy_signal.

PlanInterpreter

Valida el plan y normaliza cada acción. Tipos de acción soportados:

open_positionadd_to_position close_positionreduce_position move_stop_lossmove_take_profit place_pending_ordercancel_pending_order replace_pending_order
SpecModos
size_specfixed_lots, risk_pct_of_equity, volume, formula (volume_ratio_based).
stop_specprice, price_offset/points_from_entry, atr_multiple, break_even(_plus).
take_profit_specprice, price_offset, rr_multiple, multi_target.

Si el plan es estructuralmente inválido lanza PlanValidationError y el plan se marca rejected_structural.

ExecutionEngine

Ejecuta las acciones normalizadas contra el IBrokerAdapter y persiste los recursos canónicos: por cada apertura crea un leg, su entry_group y un fill; al cerrar actualiza legs/grupos. Genera un execution_report y un action_report por acción, más eventos en el event_log. Estados de acción posibles: executed, rejected_broker, rejected_technical, not_supported, error. Todo el almacenamiento se describe en Persistencia.

Fuente (código): main.py (_run_v1_strategy_cycle), src/runtime/{adapter,context_builder,plan_interpreter,execution_engine,state_store}.py.
