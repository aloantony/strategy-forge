Runtime

Runtime live (main.py)

El loop headless carga las estrategias, las analiza en paralelo respetando un timeout y enruta cada señal por el camino v1 o por el legacy. Es el mismo motor que usa el botón Iniciar motor de la GUI.

Arranque (main())

  1. Si PERSISTENCE_ENABLED, llama a bootstrap_persistence(PERSISTENCE_DB_PATH) y guarda la conexión.
  2. load_active_strategies() descubre y carga las estrategias.
  3. mt5_connection.initialize_mt5() y check_symbol(SYMBOL).
  4. run_bot_loop(entries) y, al terminar, mt5.shutdown() + cierre de la DB.

El loop (run_bot_loop)

Por cada iteración:

  • Comprueba is_market_open(SYMBOL) y construye un market_cache con un DataFrame enriquecido por cada timeframe distinto.
  • Scheduler justo: ordena las estrategias por su última ejecución (last_analyzed_ts) para que ninguna quede rezagada.
  • Análisis concurrente: envía _analyze_strategy a un ThreadPoolExecutor y espera con wait(timeout=…); las que no terminan a tiempo se marcan como timeout. Si solo hay 1 worker, va en serie.
  • Aplica las señales bajo ORDER_EXECUTION_LOCK, hasta MAX_ORDERS_PER_ITERATION órdenes por ciclo.
ℹ Espera del loop

El intervalo de espera no es SLEEP_SECONDS: run_bot_loop usa timeframe_to_seconds(min_timeframe) — p.ej. 60 s si la estrategia más rápida es M1.

Enrutado: v1 vs legacy

Se usa la ruta v1 cuando STRATEGY_RUNTIME_MODE == "v1_only" y PLAN_EXECUTOR_ENABLED y la persistencia está activa. En ese caso cada estrategia pasa por _run_v1_strategy_cycle (ver Runtime v1). Si no, se usa la ruta legacy:

pyramiding + buy + ATR>0
trading.apply_pyramid_signal (con lote dinámico si dynamic_sizing y volume_ratio > 0).
resto de señales
trading.apply_signal con LOT, SL_POINTS, TP_POINTS.

Análisis de una estrategia

_analyze_strategy aplica apply_strategy_processing y luego get_strategy_signal_payload (pasando params si el módulo los acepta). Devuelve signal, reason, pyramiding, atr_value, dynamic_sizing, volume_ratio o un error.

Concurrencia y límites

max_workers
STRATEGY_MAX_WORKERS (o 8); acotado al nº de estrategias.
analysis_timeout
STRATEGY_ANALYSIS_TIMEOUT_SECONDS (mín. 1 s).
max_orders_per_iteration
MAX_ORDERS_PER_ITERATION, acotado al nº de estrategias.
magic number
override > MAGIC_NUMBER del módulo > base·1000 + (crc32(key) % 997 + 1) en multi-estrategia.
