Herramientas

Backtesting

El motor de backtesting/runtime.py simula vela a vela usando el mismo contrato de estrategia que el runtime y las mismas fuentes de datos. Se ejecuta desde la GUI o la CLI, con datos de MT5 o Dukascopy.

Cómo simula (BacktestEngine)

  • Construye el DataFrame de mercado con warmup previo y aplica el procesamiento de la estrategia.
  • La señal se calcula sobre la vela cerrada y se aplica en la apertura de la vela siguiente (patrón pending_signal).
  • En cada vela: comprueba SL/TP, marca equity y, si hay señal pendiente, la ejecuta.
  • Dos modos de posición: standard (invierte al recibir señal opuesta) y advanced (pirámide solo de compras, con SL/TP por ATR).
  • Motivos de salida: SL, TP, REVERSAL, END_OF_RANGE. El PnL usa tick_value/tick_size.

La petición (BacktestRequest)

CampoSignificado / default
strategy_key, strategy_label, moduleEstrategia a evaluar.
symbolInstrumento.
timeframe_valueConstante MT5 del timeframe.
start_date, end_dateRango en UTC.
initial_balanceBalance inicial (> 0).
warmup_barsVelas de calentamiento; por defecto max(BARS_HISTORY, 500) = 500.
lot, sl_points, tp_pointsTamaño y stops.
spread_points, slippage_points, commission_per_lotCostes de simulación (default 0.0).
data_provider"mt5" (default) | "dukascopy".

Funciones públicas: run_backtest(request, data_source=None) y run_backtest_comparison(...) (agrupa estrategias por timeframe, reutiliza el DataFrame y devuelve la clave strategies con un resumen por estrategia).

Métricas devueltas

El resultado status: "success" incluye, entre otros:

total_return_pctfinal_balance total_profitwin_rate closed_tradeswinning/losing_trades max_drawdownprofit_factor avg_win / avg_lossexpectancy trades[]equity_curve[] drawdown_curve[]

Cada trade incluye entry/exit_time, entry/exit_price, direction, volume, profit, reason, mode; cada punto de equity es {time, equity, balance}.

CLI: python -m backtesting runtime

python -m backtesting runtime \
  --strategy-module strategies.strategy_primera_estrategia \
  --symbol "#Germany40" --timeframe H1 \
  --start 2024-01-01 --end 2024-12-31 \
  --initial-balance 10000 --lot 0.01 \
  --sl-points 300 --tp-points 500 \
  --data-source dukascopy
ArgumentoDefault
--strategy-key / --strategy-module / --strategy-labelDe config / vacío.
--symbolconfig.SYMBOL
--timeframeVacío → timeframe de la estrategia o M1.
--start / --endRequeridos (--end se toma a fin de día).
--initial-balance10000.0
--warmup-bars0 → el motor usa 500.
--lot / --sl-points / --tp-pointsDe config.
--data-sourcemt5 (o dukascopy).
ℹ El CLI no expone costes

spread_points, slippage_points y commission_per_lot existen en BacktestRequest pero no son argumentos del CLI; solo se fijan vía dict (p.ej. desde la GUI). El resultado se imprime como JSON.

Orquestación: BacktestService

src/application/backtest_service.py aísla la construcción y validación de la petición de la UI. Valida símbolo, fechas (parseadas de hora local a UTC) y balance; resuelve la fuente de datos; y fija warmup_bars = max(BARS_HISTORY, 500). 

service = BacktestService()
prepared = service.prepare_run(payload, strategy_entry)     # valida + resuelve datasource
result   = service.execute_run(prepared.request, prepared.data_source)

Métodos: prepare_run, prepare_comparison (≥ 2 estrategias), execute_run, execute_comparison, parse_date, dukascopy_available. backtest.py en la raíz es el backtester legacy, en desuso.

Fuente (código): backtesting/runtime.py, backtesting/cli.py, src/application/backtest_service.py.
