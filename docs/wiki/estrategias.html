Estrategias

Sistema de estrategias

Las estrategias viven en strategies/ como módulos Python independientes. El runtime las descubre, prepara su DataFrame y les pide una señal. Hay dos APIs: la legacy (v0) basada en señales y la v1 basada en decide().

buy sell none df.iloc[-2] = vela cerrada

Qué invoca el runtime

strategy_runtime.apply_strategy_processing llama, si existen, prepare_dataframe(df) y luego compute_dir1_and_signals(df, enable) o compute_signals(df, enable). Después, get_strategy_signal_payload intenta get_last_signal_payload(...) y, si no existe, get_last_signal(...).

Contrato mínimo (API v0)

def get_last_signal(df: pd.DataFrame, verbose: bool = False) -> str:
    # Devuelve "buy", "sell" o "none". Usa df.iloc[-2] (vela cerrada).
    if df is None or len(df) < 3:
        return "none"
    row = df.iloc[-2]

Parámetros (PARAMS)

Si el módulo define PARAMS, main.py lo valida con _validate_params_schema: cada entrada debe ser {type: "int"|"float", default, min, max, label} con min ≤ default ≤ max. Los valores por defecto se fusionan con un fichero <módulo>.params.json (si existe, con clamp a los límites). Si la función de señal acepta un kwarg params (o **kwargs), el runtime se lo pasa. 

PARAMS = {
    "rsi_length": {"type": "int", "default": 14, "min": 2, "max": 50, "label": "RSI length"},
}

def get_last_signal_payload(df, verbose=False, params=None):
    length = (params or {}).get("rsi_length", 14)
    ...

API v1 (decide / plan)

Una estrategia v1 se marca con STRATEGY_API_VERSION = 1 e implementa decide(context, state), que devuelve {"plan": …, "next_state": …}. Opcionalmente initial_state(context) se llama en la primera iteración. 

STRATEGY_API_VERSION = 1

def initial_state(context: dict) -> dict:      # opcional
    return {"holdings": 0}

def decide(context: dict, state: dict) -> dict:
    return {"plan": {"actions": [...], "reason": "..."}, "next_state": state}
ℹ Coexistencia v0 / v1

Con STRATEGY_RUNTIME_MODE = "v1_only", load_active_strategies descarta los módulos que no sean v1. Las estrategias v0 siguen funcionando porque el LegacyStrategyAdapter presenta get_last_signal como un decide(). Detalle en Runtime v1.

Descubrimiento y magic number

  • Descubrimiento: load_active_strategies escanea STRATEGY_DIR, resuelve ACTIVE_STRATEGIES (o la clave por defecto, o la primera encontrada) y prueba referencias como strategies.<key> y strategies.strategy_<key>.
  • Magic number: override explícito > MAGIC_NUMBER del módulo > base de config. En multi-estrategia: base·1000 + (crc32(key) % 997 + 1).
⚠ Regla de aislamiento

Según el README.md, una estrategia debe mantenerse desacoplada: evita importar config, data_feed, trading, mt5_connection o la GUI. Recibe un DataFrame preparado y devuelve señales, sin IO ni conexiones.

Ejemplo real: ADX + DI

strategies/strategy_primera_estrategia.py (generada por el Strategy Builder) solo importa pandas. Define TIMEFRAME = "H1", MAGIC_NUMBER = 42501 y añade en prepare_dataframe las columnas atr_14, atr_pct_14, adx_14, plus_di_14, minus_di_14, plus_di_cross_14, minus_di_cross_14, volume_ratio_20. 

def get_last_signal(df, verbose=False):
    if df is None or len(df) < 3:
        return "none"
    if df.iloc[-2]["adx_14"] > 25 and df.iloc[-2]["plus_di_cross_14"] > 0:
        return "buy"
    elif df.iloc[-2]["adx_14"] < 0:
        return "sell"
    return "none"

def get_last_signal_payload(df, verbose=False):
    signal = get_last_signal(df, verbose=verbose)
    if signal == "buy":
        return {"signal": "buy", "reason": "...",
                "pyramiding": True, "dynamic_sizing": True,
                "atr_value": df.iloc[-2]["atr_14"],
                "volume_ratio": df.iloc[-2]["volume_ratio_20"]}
    return {"signal": signal, "reason": "..."}
