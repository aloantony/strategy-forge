Proyecto

Testing

La suite usa pytest con descubrimiento estándar. Está diseñada para correr sin un MT5 real: las fuentes de datos, el broker y MT5 se sustituyen por mocks, de modo que cubre runtime, datos, builder y persistencia de forma aislada.

Cómo ejecutarla

# Toda la suite
pytest tests/

# Un archivo, con detalle
pytest tests/test_runtime.py -v

# Una clase / test concretos
pytest tests/test_persistence.py -k state -v

Cobertura por archivo

Número de funciones test_* reales por archivo y qué cubren:

ArchivoTestsQué cubre
test_runtime.py32Adapter legacy, PlanInterpreter (specs, action types) y StrategyStateStore con MT5 mockeado.
test_persistence.py23DAL / UnitOfWork y migraciones (instancias, planes, fills, event log).
test_data_factory.py19Resolución de símbolo canónico y build_data_source.
test_dukascopy_historical_source.py17Fetch de Dukascopy y normalización de schema (mock de fetch).
test_builder.py11Generación de estrategias y validación AST.
test_backtest_runtime.py4Lógica del BacktestEngine.
test_backtest_service.py4Orquestación del BacktestService.
test_market_status.py3trading.is_market_open.
test_backtesting_cli.py1Parseo/enrutado del CLI de backtesting.
ℹ Sin MT5 para testear

Ningún test requiere conexión MT5 real. test_persistence y test_runtime usan bootstrap_persistence sobre una base temporal. Se omite test_dispatch.py aquí porque pertenece al sistema de hooks de .claude/, fuera del alcance de esta wiki.

Fuente (código): tests/*.py (conteo de funciones test_* directo del repositorio).
